# 素材库与 API 调用记录

侧边栏「资产」下的两个跨项目视图：**素材库**汇总项目产出、导入素材和视频复刻登记的图片、视频与音频，**API 调用记录**汇总所有模型请求及其花费。素材库支持删除素材及可清理的本地文件；API 调用记录的清空只删除日志，不影响媒体文件。

## 素材库（/materials）

一条素材是 `assets` 表里的一行（项目产出）或 `library_assets` 表里的一行（手动导入及视频复刻登记）。项目产出不额外落库，因此功能上线前生成的素材同样可见。

- 默认卡片瀑布流（按原始比例排版，9:16 与 1:1 并排不裁切），可切换列表模式；滚动到底自动加载下一页，每页 24 条。
- 筛选：图片/视频/音频、来源标签、平台、模型、项目，以及「仅看在用的」（同一镜头可能有多个版本，只有选中的版本参与合成）。搜索覆盖提示词、模型、项目名、作者，以及导入素材的名称、描述与标签。
- 卡片点开是完整档案：来源与所属分镜、平台与模型、输入提示词、生成输入（生成模式、参考图/参考视频、音频方案、时长）、输出文件与体积、生成时间；免费素材库来源额外保留原始链接、作者与授权，便于导出时生成署名。
- 视频卡片鼠标悬停即播放，详情里是带控制条的播放器；音频提供播放控件。视频卡片、列表和详情展示实测宽高（例如 `496 × 864`、`1080 × 1920`），没有元数据时显示未知，不根据模型名称推测。导入视频使用入库宽高；旧本地视频仅对当前页做有界并发探测，并按文件大小及修改时间持久缓存元数据，浏览列表时不会为探测宽高而下载云视频。
- 普通文件走本地 `/api/files`；Agent 超分文件走稳定的 `/api/agent-studio/resources/<requestId>`。超分完成时登记对象位置、SHA-256、大小及宽高；首次访问才由本地服务签名读取并校验后缓存到 `cache/agent-media/<sha256>.mp4`。后续播放、Range 请求和下载均复用本地缓存，不依赖会过期的平台地址。既有已下载的超分产物直接迁入缓存，不重新下载。
- 接口：`GET /api/materials?mediaType=&source=&origin=&provider=&model=&projectId=&q=&selectedOnly=1&offset=&limit=`，返回 `items`、`total`、`hasMore` 与筛选项 `facets`。`source` 按来源标签筛选，兼容保留的 `origin` 按原存储来源筛选；例如 Agent 复刻图片的 `source` 是 `agent_remake`，`origin` 仍可能是 `ai_generated`。来源筛选在分页前执行，`facets.sources` 返回整个扫描范围的来源计数。单次最多扫描最近 4000 条素材，超出时响应里 `truncated` 为 true，页面会提示。
- 详情中的「删除」需确认后执行 `DELETE /api/materials/{id}`，删除对应记录并清理可删除的本地文件；已有视频复刻草稿仍引用该素材 ID 或文件路径时返回 409，需先移除项目引用。云端副本不随此操作删除。

### 来源标签与素材选择

素材、商品及主播统一使用自动来源标签：AI 生成、本地上传、链接导入、Agent 复刻、视频复刻、免费素材库、商品素材、内置示例、手动添加、来源未知。标签描述获取流程，不推断人物是真人还是虚拟人；原有自定义内容标签继续保留。

商品和主播按图片记录 `imageSources`，因此同一主播上传的原照片与 AI 生成的定妆图可以分别筛选。既有记录仅在本地路径、项目类型或既有登记信息能证明来源时补充展示，否则标为来源未知。使用 `src/lib/material-source.ts` 统一解析，避免不同页面自行猜测。

素材库、商品库和主播库及其选择入口均展示来源。共用图片/视频素材弹窗提供来源按钮，仍遵守调用方限定的图片或视频类型；商品图片弹窗还支持商品类目按钮。来源可以和搜索组合使用，切换来源时清空旧分页，过期请求不能把旧列表追加回来。Agent 参考池及按段分配选项显示来源，版本素材快照保留选中图片的来源；场地来源由服务器按真实素材记录校正。

### 导入素材

页面右上角的「导入素材」把不是项目产出的素材也收进同一个库：两条入口，一份描述表单。导入的素材不属于任何项目，也不占分镜——它记在独立的 `library_assets` 表里，`assets.projectId` 仍然是硬约束，两份数据只在 `/api/materials` 的读取侧合并。

- **本地上传**：从磁盘选文件。支持 MP4、WebM、MOV、M4V、JPG、PNG、WebP，单个不超过 80MB。
- **链接导入**：粘贴视频直链，由服务器下载入库。直链一般用 Chrome 视频下载助手一类的插件在播放页取到（通常以 `.mp4` 结尾）——比先存到「下载」再挑回来快一步；粘贴网页地址会明确报错，不会存成一个打不开的「视频」。
- 两条入口都填同一份信息：名称（必填，留空时用文件名或链接末段兜底）、描述、标签（逗号或空格分隔，最多 12 个）、作者、授权、原始链接（链接导入默认就是那条链接）。生成的素材还有提示词可以搜，导入的素材只有这段话——它就是以后把素材找回来的唯一线索，搜索、卡片标题、详情都用它。
- 文件流式落盘后按内容哈希命名存进 `data/uploads/_library/`，同一个文件重复导入不会占两份空间；落盘后用 ffprobe 复核，真实格式与扩展名对不上（比如失效直链返回的是一张错误页）直接拒绝，并顺带记下分辨率与时长。
- 链接下载走 `safeFetch`：内网、回环、云元数据等地址一律拒绝，每一跳重新校验；整体超时 180 秒，体积同样受 80MB 上限约束。
- 接口：`POST /api/materials/import`。`multipart/form-data`（`file` + 各描述字段）是上传，`application/json`（`{ url, title, description, tags, author, license, sourceUrl }`）是链接导入。
- 上传体积还受一道非本地的闸门：`src/proxy.ts` 匹配 `/api/:path*`，被匹配的请求体会被 Next 缓冲以便代理和路由都能读，默认 10MB 以上直接**截断**（路由拿到半截 multipart，只能报解析失败）。`next.config.ts` 里的 `experimental.proxyClientMaxBodySize` 因此设为 `96mb`：给 80MB 文件的 multipart 外壳留出余量，真正拒绝超限文件的仍是路由本身（返回 413 并说明原因）。改动 80MB 上限时这两个数要一起看。

## API 调用记录（/api-logs）

每一次发往模型的 HTTP 请求都会记一行，**包括失败和 SDK 自动重试**——同一次生成重试三次就是三行，这正是账单对不上时需要看到的。记录发生在三个汇合点（LLM 客户端工厂、媒体 Provider 工厂、配音入口），新增调用点无需改动即可被记录。

- 默认按项目聚合，按最近调用时间排序：每个项目显示调用次数、失败数和花费合计，点击项目名展开内部调用记录。未关联项目的调用单独聚合，已删除项目按原项目 ID 保留分组。
- 可按设置里的模型类型筛选：文本、视觉、生图、生视频、配音。带图片的文本请求会自动归到视觉；搜索支持项目名、模型、提示词和返回内容。
- 项目花费与顶部汇总都统计当前筛选范围内的全部记录，不受分页影响；无价格的调用单独提示。项目列表与每个项目的调用明细独立分页，展开后可加载该项目全部记录。
- 每行记录：场景（脚本生成/单镜重写/评审/商品分析/质量评估/分镜/修复/配音…）、平台与模型、接口、所属项目与分镜、输入摘要、输出摘要、用量、花费、耗时、状态；展开可看完整的请求与返回 JSON。
- 顶部汇总当前筛选范围内的调用次数、失败数、输入/输出 Token、输入/输出花费与平均耗时。
- 「清空记录」只删除记录本身。默认最多保留最近 5000 条，超出后自动清理最旧的。项目和作品卡片另按调用 ID 保存累计费用，人民币与美元分别合计；清空或淘汰日志不清除已累计的项目费用，因此卡片累计值可以大于当前日志筛选汇总。未定价调用单独提示。
- 接口：`GET /api/api-calls?groupBy=project&offset=&limit=` 返回 `groups`、`totalProjects` 和全量筛选汇总；明细使用 `projectId=`，未关联项目明细使用 `unassigned=1`。两种视图共用模型类型、场景、平台、模型、状态、时间与搜索筛选。

### 安全与体积

- API Key 永不落库：键名形如 `apiKey`、`authorization`、`token`、`secret` 的字段在序列化前就被替换为 `[redacted]`。
- 参考图、首帧等 data URI 与 base64 大块内容只记体积占位（如 `[inline image/png, ~820KB]`）；单字段超过 4000 字符截断，单条记录超过 24000 字符整体压缩。

### 花费是怎么算的

按可测量的用量（Token、图片张数、视频秒数、配音字符数）乘以费率，费率取值顺序：

1. 平台自己公布的单价（如 Atlas 模型目录里的 `priceBase`）；
2. `data/model-pricing.json`；
3. 内置价目表（`src/lib/model-pricing.ts`，2026-09 采集的公开报价）。

三者都没有覆盖到的模型不会编造数字：该行花费显示「—」，汇总里也会提示「其中 N 次无价目表价格，未计入」。本机 Ollama 等免费端点直接记为 0。

百炼 Wan 3.0 / Prime 视频另按地域、分辨率与公开人民币单价估算，输入和输出视频均计费；回执中的 `usage.duration` 已含两者合计，不再次叠加输入。人民币金额不折算并入美元。页面金额是用量乘单价的估算，不是账户实付账单；具体规则与验证记录见[复刻任务计费与发布导出](task-costs-and-publishing.md)。

内置价目表只是估算，实际合同价不同的话，在数据目录建 `data/model-pricing.json` 覆盖（`match` 是对模型 ID 的大小写不敏感正则，改动保存后下一次调用即生效）：

```json
{
  "token": [{ "match": "^my-model", "rate": { "input": 1.0, "output": 3.0, "cachedInput": 0.1 } }],
  "media": [
    { "match": "^my-image-model", "rate": { "perImage": 0.02 } },
    { "match": "^my-video-model", "rate": { "perVideoSecond": 0.05 } },
    { "match": "^my-tts-model", "rate": { "perMillionChars": 30 } }
  ]
}
```

异步生视频在**提交任务时**就记一行并保存预估费用；结果返回后补写输出、最终状态与可测量的费用，恢复查询按原平台与任务 ID 修订原调用，不重复累计同一任务。失联则在原行留下原因，不能把结果不明当作免费。Agent 工作室的持久回执也汇入同一调用记录。


## 素材库与主播库的 AI 生图

`/materials` 和 `/presenters`（以及设置中的主播管理）均提供「AI 生成」入口。弹窗中填写名称、画面描述和比例，选择已启用平台的图片模型。支持现有目录中的 Seedream 等文生图模型；Seedance 是视频模型，不列在生图菜单。模型选择复用设置中的平台分组、模型名、模型 ID、场景标签和价格，明确区分平台报价、估算与未知价格；不会修改全局默认模型。

每次点击只提交一张，生成期间禁止重复提交和关闭弹窗，成功后预览。`POST /api/materials/generate` 调用所选平台并将临时 URL / data URI 图片下载、校验、保存到本地，再在 `library_assets` 中记录 `generated` 来源、provider、model、prompt。迁移 `0027_library_generation` 自动补齐三个可空列，旧导入不受影响。生成记录在素材库可按 AI 生成来源、平台、模型和提示词筛选；费用记录由现有 provider 日志层保存。

素材图保存于 `uploads/library-generated/`。主播原图保存于 `uploads/characters/`，浏览器沿用既有持久主播库，将原图作为 sourcePhotos；不将单幅头像误作四视图定妆图，也不自动追加一次付费定妆生成。原图同时出现在素材库，删除此素材库条目不删除主播原图。主播之后可以继续编辑、生成多视图或用作复刻参考。

生成接口不自动重试付费提交。失败时显示上游或保存错误；若上游已计费但下载/入库失败，应先查看 API 调用记录中的返回信息，避免直接重复生成。测试使用模拟生成接口与真实内存数据库迁移，不消耗模型额度。


## 商品库的 AI 生图

`/products` 顶部及新建 / 编辑商品的图片区提供「AI 生成商品图」。可直接从文本描述生成，也可切换到「参考图片生成」，上传一张 JPG / PNG / WebP（最大 20MB）或选择当前商品的已有图片。模型菜单按文生图 / 图生图能力筛选，不会将只支持文本生成的模型用于参考图生成；平台、模型与价格仍在弹窗中显示。图片比例可选 1:1、9:16 和 16:9。

生成结果先加入当前商品表单，可继续修改名称、类目、卖点、价格和目标人群，点击「添加商品」或「保存修改」后才写入浏览器商品库。每个商品最多 5 张图片，可把任意图片设为封面。新增图片不替换已有图片，生成失败不会改动已保存商品。AI 可能改变商品外观细节，保存前应检查结果。

复用 `POST /api/materials/generate`，新增 `destination: "product"`，通过 `mode: "text-to-image" | "image-to-image"` 和 `referenceImageUrl` 区分两种生成方式。服务器在调用模型前校验参考图，将本地 `/api/files` 路径转换为 data URI；无效或丢失的参考图直接拒绝，不退回文生图。纯文本模式忽略旧参考图。每次提交调用一次生成，失败不自动重试。

商品原图存于 `uploads/product-generated/`，并在素材库登记平台、模型和提示词；API 调用场景为 `product_image`。删除素材库条目保留商品原图，避免破坏仍在浏览器商品库中使用的图片。取消商品表单也不会删除已生成的素材。相关自动化回归使用模拟模型响应，不代表真实平台生成验收。
