# 素材库与 API 调用记录

侧边栏「资产」下的两个跨项目视图：**素材库**汇总所有项目产出的图片与视频，**API 调用记录**汇总所有模型请求及其花费。两者都是只读视图，删除记录不会影响已生成的文件。

## 素材库（/materials）

一条素材是 `assets` 表里的一行（项目产出）或 `library_assets` 表里的一行（手动导入）。项目产出不额外落库，因此功能上线前生成的素材同样可见。

- 默认卡片瀑布流（按原始比例排版，9:16 与 1:1 并排不裁切），可切换列表模式；滚动到底自动加载下一页，每页 24 条。
- 筛选：图片/视频、来源（模型生成 / 免费素材库 / 本地上传 / 链接导入 / 商品图）、平台、模型、项目，以及「仅看在用的」（同一镜头可能有多个版本，只有选中的版本参与合成）。搜索覆盖提示词、模型、项目名、作者，以及导入素材的名称、描述与标签。
- 卡片点开是完整档案：来源与所属分镜、平台与模型、输入提示词、生成输入（生成模式、参考图/参考视频、音频方案、时长）、输出文件与体积、生成时间；免费素材库来源额外保留原始链接、作者与授权，便于导出时生成署名。
- 视频卡片鼠标悬停即播放，详情里是带控制条的播放器；文件全部走本地 `/api/files` 路径，不依赖会过期的平台地址。
- 接口：`GET /api/materials?mediaType=&origin=&provider=&model=&projectId=&q=&selectedOnly=1&offset=&limit=`，返回 `items`、`total`、`hasMore` 与筛选项 `facets`。单次最多扫描最近 4000 条素材，超出时响应里 `truncated` 为 true，页面会提示。

### 导入素材

页面右上角的「导入素材」把不是项目产出的素材也收进同一个库：两条入口，一份描述表单。导入的素材不属于任何项目，也不占分镜——它记在独立的 `library_assets` 表里，`assets.projectId` 仍然是硬约束，两份数据只在 `/api/materials` 的读取侧合并。

- **本地上传**：从磁盘选文件。支持 MP4、WebM、MOV、M4V、JPG、PNG、WebP，单个不超过 80MB。
- **链接导入**：粘贴视频直链，由服务器下载入库。直链一般用 Chrome 视频下载助手一类的插件在播放页取到（通常以 `.mp4` 结尾）——比先存到「下载」再挑回来快一步；粘贴网页地址会明确报错，不会存成一个打不开的「视频」。
- 两条入口都填同一份信息：名称（必填，留空时用文件名或链接末段兜底）、描述、标签（逗号或空格分隔，最多 12 个）、作者、授权、原始链接（链接导入默认就是那条链接）。生成的素材还有提示词可以搜，导入的素材只有这段话——它就是以后把素材找回来的唯一线索，搜索、卡片标题、详情都用它。
- 文件流式落盘后按内容哈希命名存进 `data/uploads/_library/`，同一个文件重复导入不会占两份空间；落盘后用 ffprobe 复核，真实格式与扩展名对不上（比如失效直链返回的是一张错误页）直接拒绝，并顺带记下分辨率与时长。
- 链接下载走 `safeFetch`：内网、回环、云元数据等地址一律拒绝，每一跳重新校验；整体超时 180 秒，体积同样受 80MB 上限约束。
- 接口：`POST /api/materials/import`。`multipart/form-data`（`file` + 各描述字段）是上传，`application/json`（`{ url, title, description, tags, author, license, sourceUrl }`）是链接导入。
- 上传体积还受一道非本地的闸门：`src/proxy.ts` 匹配 `/api/:path*`，被匹配的请求体会被 Next 缓冲以便代理和路由都能读，默认 10MB 以上直接**截断**（路由拿到半截 multipart，只能报解析失败）。`next.config.ts` 里的 `experimental.proxyClientMaxBodySize` 因此设为 `96mb`：给 80MB 文件的 multipart 外壳留出余量，真正拒绝超限文件的仍是路由本身（返回 413 并说明原因）。改动 80MB 上限时这两个数要一起看。

## API 调用记录（/api-logs）

每一次发往模型的 HTTP 请求都会记一行，**包括失败和 SDK 自动重试**——同一次生成重试三次就是三行，这正是账单对不上时需要看到的。记录发生在三个汇合点（LLM 客户端工厂、媒体 Provider 工厂、配音入口），新增调用点无需改动即可被记录。

- 按设置里的模型类型分区：文本、视觉、生图、生视频、配音。带图片的文本请求会自动归到视觉。
- 每行记录：场景（脚本生成/单镜重写/评审/商品分析/质量评估/分镜/修复/配音…）、平台与模型、接口、所属项目与分镜、输入摘要、输出摘要、用量、花费、耗时、状态；展开可看完整的请求与返回 JSON。
- 顶部汇总当前筛选范围内的调用次数、失败数、输入/输出 Token、输入/输出花费与平均耗时。
- 「清空记录」只删除记录本身。默认最多保留最近 5000 条，超出后自动清理最旧的。

### 安全与体积

- API Key 永不落库：键名形如 `apiKey`、`authorization`、`token`、`secret` 的字段在序列化前就被替换为 `[redacted]`。
- 参考图、首帧等 data URI 与 base64 大块内容只记体积占位（如 `[inline image/png, ~820KB]`）；单字段超过 4000 字符截断，单条记录超过 24000 字符整体压缩。

### 花费是怎么算的

按可测量的用量（Token、图片张数、视频秒数、配音字符数）乘以费率，费率取值顺序：

1. 平台自己公布的单价（如 Atlas 模型目录里的 `priceBase`）；
2. `data/model-pricing.json`；
3. 内置价目表（`src/lib/model-pricing.ts`，2026-09 采集的公开报价）。

三者都没有覆盖到的模型不会编造数字：该行花费显示「—」，汇总里也会提示「其中 N 次无价目表价格，未计入」。本机 Ollama 等免费端点直接记为 0。

内置价目表只是估算，实际合同价不同的话，在数据目录建 `data/model-pricing.json` 覆盖（`match` 是对模型 ID 的大小写不敏感正则，改动保存后下一次调用即生效）：

```json
{
  "token": [{ "match": "^my-model", "rate": { "input": 1.0, "output": 3.0, "cachedInput": 0.1 } }],
  "media": [
    { "match": "^my-image-model", "rate": { "perImage": 0.02 } },
    { "match": "^my-video-model", "rate": { "perVideoSecond": 0.05 } },
    { "match": "^my-tts-model", "rate": { "perMillionChars": 30 } }
  ]
}
```

异步生视频在**提交任务时**就记一行并计入花费——任务一旦提交就会计费，不能等结果回来才记；结果返回后补写输出与最终状态，失联则在原行留下原因。
